## 二维定位结果

保持原网络、loss和1e-3学习率。最后1000步checkpoint固定选择，没有按development效果选择权重。训练loss前50步均值7.5453，后50步均值4.4382；这只说明优化在进行，不是稳定收敛。

| 指标 | train | development |
| --- | ---: | ---: |
| 帧数 | 740 | 236 |
| 可见角点误差：逐帧均值的中位数 | 2.192 px | 2.558 px |
| 可见角点误差：逐帧均值的P90 | 7.607 px | 7.358 px |
| 可见性precision（0.8阈值） | 93.75% | 96.25% |
| 可见性recall（0.8阈值） | 47.58% | 50.81% |
| learned几何有效位姿 | 0/740 | 0/236 |

像素误差按每帧整组四重对称匹配后计算，只在有可见GT点的帧上统计；不是全部关键点混合后的分位数。位姿有效率的分母是全部manifest帧，拒绝不会被移除。无有效位姿时位置/姿态误差记null，而非零。

development腕部视角像素误差中位数3.247 px、可见性recall 60.13%；外部视角没有预测置信度达到0.8的角点，可见性recall为0。全局precision不能掩盖这一分组差异。

## 三维测量为何失败

先把网络替换为GT角点，但继续使用原始渲染深度和不变几何阈值：

| 数据 | GT关键点几何有效率 | 2mm/5°以内占全部帧 |
| --- | ---: | ---: |
| pilot | 6/188（3.19%） | 5/188（2.66%） |
| 主集 | 7/976（0.72%） | 5/976（0.51%） |

主集拒绝原因为可见深度点不足519帧、刚体拟合拒绝450帧。外部相机有效位姿0/488，腕部相机7/488。

逐点核验：2415个可见GT角点中，1138个最近像素不属于方块，1250个最近像素深度偏差超过3mm；腕部相机1971个可见角点中，1099个最近像素落在其他物体/背景上。深度误差中位数3.50mm、P90为39.76mm。另有76个GT角点本身处于当前5cm最小深度范围以内。

这是当前方法的具体限制：角点位于深度不连续的轮廓处，图像中的亚像素角点与最近深度像素未必对应同一个表面；外部视角又经常被机器人遮挡。不能通过继续拟合图像loss自动消除这个问题。

独立诊断中，仅把GT角点对应的深度替换成理论深度，459个至少有3个可见角点的帧中421个能通过拟合。此为**privileged隔离诊断**，不是可部署结果、不是新算法，也不是无条件性能上界。实际测量路径没有使用GT深度或mask，也未放宽阈值。

## 审查与停止状态

独立只读审查由实际运行的 `gpt-5.6-sol / high` 完成。两项问题已修复并复核关闭：逐帧直立方块合同检查、checkpoint与manifest身份绑定。新增测试覆盖后者；场景状态、拒绝记录和phase覆盖独立报告。

本轮结果为：数据链路与二维训练实现有效，三维测量存在已定位的失败原因；1000步pilot没有证明收敛。没有加载Qwen/正式学生权重，没有生成学生闭环结果，没有继续训练或恢复heartbeat。

下一步优先研究对深度边缘不敏感的几何恢复，例如已知物体模型下的2D–3D位姿求解并用面内深度验证，或将测量点改为稳定表面点。应先用当前已保存数据做离线对照；不要先扩大BC预算或把GT深度接入学生。
