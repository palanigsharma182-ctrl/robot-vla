后续共享学生方案已停止，改为 [七个独立技能策略与上层调度](hierarchical_policy_plan.md)：分别验收后保留七策略，由上层选择和切换。[初始训练方案](independent_training_plan.md) 保留当时的设计状态；独立 BC、DAgger 与采样覆盖对照的最新完成结果见 [七独立策略结果](../seven_skill_dagger/results.md)，不改变以下共享学生首轮历史结果。

2026-09-08，用户批准教师接管验证 → 纠偏样本 → 等更新数BC/DAgger对照。新实验身份为`skill-dagger-r1`；此前metric-bc-v2未触发C1–C4，此处是新假设检验，不追认旧规则已通过。

固定学生为metric-bc-v2的A最终权重（SHA256 `7cf5c95ba7dbe31843d615d7a550f9d1422167f3cc6e056dfefea8ee0e68b957`），选取不依据当时仍在运行的保留开发组结果。原教师、学生输入与TCP动作合同复用；不修改canonical数据集或核心模型。

1. **接管pilot**：合格train manifest按seed排序的前8个场景，每场景独立reset后分别执行60和120个学生控制步，共16个计划单元。相同场景前缀使用相同采样seed。提前执行异常、已终止、或已稳定抓持记失败/no_candidate，均留在计划分母。教师接管最多120步，从真实当前状态重新规划到预抓取点、抓取点、闭爪；当前canonical抓取子目标已完成且连续3帧相对抓持稳定才记恢复成功。至少12/16恢复成功、覆盖至少6/8场景且标签审计通过，才自动继续第二步。未通过就停止该分支并报告，不反复换seed。
2. **聚合纠偏数据**：pilot数据保留；扩至排序前32个train场景、各两个相同接管时刻，共64个计划单元（含pilot），学生/教师每单元各最多120步，总上限15,360控制步。失败原始轨迹保留但不当作可靠教师标签；已验证成功接管的前16个教师动作锚点作为新窗口，要求至少4个有效未来教师动作。所有RGB、proprio、时间和命令来自同一实际session，完整学生前缀保留；监督只使用教师动作，chunk不能跨回学生动作，尾部截断单列为接管段结束而非成功终止。
3. **首轮训练比较**：BC与DAgger均从上述A权重及同一AdamW/RNG开始，各512更新、每次7窗口，AdamW 1e-5、math SDPA、BF16、冻结Qwen/Adapter/Memory，保持Memory masked。BC为7个原七技能均衡窗口；DAgger将每步轮换的2个槽替换为纠偏窗口，比例2/7，其余5个保留原示范。纠偏窗口循环打乱无放回，保留全部曝光。固定512更新选择，不选中途最好权重。

训练后复用metric-bc-v2相同F/S连续完整任务评估，固定8个反馈development场景，共原权重/BC/DAgger各16单元；只作为反复使用的开发证据，不读取那24个保留场景选择DAgger设置。主指标为完整任务成功，辅以短时抓持、执行错误；不以loss下降代替任务收益。先完成第一轮训练对照，有收益后再讨论用更新学生采第二轮；本批不自动追加更新或新场景。

实现注意：现有HierachyTeacher的正常入口检查不能被任意状态接管直接复用。恢复教师使用当前观测与物体状态重新固定目标，调用已有MPlib/关节命令执行器；不重置物理状态、不补造图像、不把GT技能或物体位姿送入学生输入。首轮只验证抓取恢复，不能宣称已验证任意Carry/Place状态下的教师接管。

执行时原metric-bc评估继续运行；采集与旧评估隔离调度，首轮训练等待旧评估退出后开始。数据/训练/结果位于独立运行目录，只发布脱敏摘要。执行异常保留恢复点并停止，不暗中恢复旧无限训练。

## 入口与依赖

本目录是隔离实验 runner，复用已有七技能数据、教师、学生、特征缓存和闭环评估器，不是独立下载即可训练的示例。需要已审计的七技能 train collection、匹配的上游模型资源、指标 BC 的配置与固定 A 最终 checkpoint。父权重 SHA 在 `run.py` 中固定，身份不符会拒绝执行。

在项目根目录使用 `PYTHONPATH=.:src python -m experiments.skill_dagger.run --help` 查看路径参数。运行依赖已有 CUDA/PyTorch、SAPIEN/ManiSkill、运动规划及离线模型环境；设置 `CUBLAS_WORKSPACE_CONFIG=:4096:8`。`--output` 必须是新目录，`--source-manifest` 绑定实际源文件哈希。可选 `--wait-for-evaluation` 指向前序作业退出标记，只负责资源排队，不代表前序评估成功。

`collect.py` 记录同一 session 的学生前缀与教师恢复；`data.py` 审计并提取教师标签；`train.py` 完成等更新数对照与完整任务评估；`run.py` 串联预算与身份检查。测试入口见结果页。

首轮结果出现前曾批准“有收益才追加”的条件分支，但核心收益门槛未通过，未启动后续轮次。当前 runner 不包含多轮自动续训实现，具体判定见结果页。
