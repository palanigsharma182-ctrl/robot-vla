# Align 失败轨迹定位（2026-09-09）

## 结论

既有轨迹显示两种问题：部分合法入口的首个chunk已向外规划；其余一些场景先接近目标，再在重新规划时持续向外移动。错误存在于学生命令目标，不能主要归结为执行跟踪或chunk后3步。当前证据定位了行为失效位置，尚未证明数据、优化或输入表征中的唯一根因。

## 对象与验证

只分析原BC、R1 DAgger、R2 DAgger各8条已完成development轨迹，共24条、2786个控制步。不重新rollout，不加载学生权重，不训练。读取实际关节状态/命令、plans、metrics与原教师sidecar的固定pregrasp目标，用云端SAPIEN/Pinocchio FK重建位姿。

重建检查全部通过：位置指标与日志最大差0.00046mm，姿态指标最大差0.00344度；FK与日志TCP位置最大差0.00057mm；将保存的TCP动作按原chunk固定轴累积后，与实际发送关节命令的FK最大差0.00973mm/0.08152度。因此本轮未发现足以解释厘米级失效的记录错位、坐标转换或动作执行映射错误。后一个角度指标使用任务四重对称距离；这里只报告通过的重建边界，不外推所有输入或硬件正确。

事后诊断阈值：处于8mm位置容差外时，完整4步chunk命令终点比chunk起点远超过1mm记一次位置退化；逐动作目标比动作前真实位置远超过0.05mm记该动作朝外。姿态类比使用5度门槛、chunk增加2度/单步增加0.1度。这些仅用于描述已有轨迹，不改变任务合同，也不等同每次局部退化必然导致任务失败。

## 汇总

| 指标 | R1 DAgger | R2 DAgger |
|---|---:|---:|
| 完整4步chunk数 | 320 | 320 |
| 命令终点位置退化>1mm | 133（41.6%） | 137（42.8%） |
| chunk第一步命令朝外 | 166/320 | 166/320 |
| 首步改善但4步终点退化>1mm | 6/320 | 2/320 |
| 命令终点改善>1mm但实际终点退化>1mm | 0/320 | 0/320 |
| 每步TCP命令与实际跟踪差中位数 | 1.415mm | 1.402mm |
| 每步跟踪差p95 | 2.703mm | 3.743mm |

跟踪误差仍可能影响后续输入，不能从0/320推出动力学毫无作用；但在这里定义的明显方向反转上，命令本身已经错误。第一步朝外比例约52%，而仅后续动作使好首步变坏的情况较少，不支持先把执行4步改1步作为主要修复。未实际验证缩短执行前缀的收益。

## 两个定位实例

1. 场景1811002，R1 DAgger：同一记录入口距目标35.09mm。第1个chunk的命令终点为37.61mm，实际执行到36.81mm；原BC同一入口的首chunk命令终点32.92mm、实际33.76mm，并最终成功。问题在首个规划输出中就存在，不依赖先积累大量学生偏移。后续不同策略状态会分叉，不能把后面的逐步差异当同状态动作对照。

2. 场景1811000，R2 DAgger：前28步从39.04mm接近到16.53mm；第29–32步出现轻微回退。第33–36步开始明确持续朝外：chunk起点16.73mm，命令终点19.93mm，实际18.56mm；第37–40步进一步命令到24.45mm，实际22.30mm。此时姿态约2.2度，已在5度范围内，但位置仍远于8mm，不是完整对齐完成后的合理退出。后续多次重规划继续增大位置误差。

## 限制与后续

几何纠偏方向不是教师在同一偏离状态下重新规划的动作标签。原评估记录没有保存完整RGB观测和可直接恢复的仿真快照，因此本轮没有查询原BC/教师在DAgger偏离状态上的输出。现有记录足以定位“哪一步、哪个chunk、命令还是跟踪”，不足以直接判断那一状态是否超出纠偏数据支持或模型是否丢失目标信息。

后续应围绕已定位的两个状态段检验：合法入口上保留原BC的正确几何动作，以及接近目标但未完成时持续纠偏。若需在完全相同偏离状态比较教师/BC/DAgger，须做有界确定性回放并逐步校验状态，重新获取真实观测；此类development诊断数据不得回用训练。不要仅靠重复当前DAgger配方、放宽8mm/5度标准或添加评估guard掩盖问题。

实现为 `diagnose_align_trace.py`，只读分析输入并写入新的诊断目录。所有原训练权重、轨迹与评估结果保持不变。原始轨迹、完整诊断输出与模型权重在私有恢复材料中保存，仓库仅提供代码和脱敏结论。
