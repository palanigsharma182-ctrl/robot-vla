# TCP Chunk 最小诊断结果

2026-09-07，`diagnostic-v2`。执行有效，264/264 窗口完成，退出码 0。这是教师状态上的离线 development / post-hoc 诊断，没有训练、仿真 step 或物理动作。

**最直接的问题是学生在训练来源的教师状态上已有明显动作误差，尤其旋转输出幅度偏大；不能仅用未见场景泛化解释。** 本轮教师标签重建与前四步 IK 检查均通过。但学生在同状态下有 263/264 个窗口通过 0.1 rad 计划限制，因此尚不能把历史闭环提前停止全部归因于这种状态下的计划超限。

## 实际范围与指标

固定原 TCP checkpoint、Qwen/Adapter/Expert/Memory、数据转换、归一化、BF16、10 步 Euler 和每窗口原 `sampling_seed(scene, anchor)`。24 条轨迹，每条 anchor 为 `0,8,...,80`：16 条 train / 8 条 development，共 176 / 88 个窗口。每窗口输出 16 步；主要动作误差和累计目标、IK 指标使用实际执行的前四步。未运行 joint-world、多噪声重复、20 步采样或闭环对照。

连续误差先在每条轨迹内平均，再报告轨迹均值；通过数的分母为窗口，不把窗口当作独立场景。

训练来源的 176 个窗口中，165 个确实被原训练采样过。仅看这 165 个窗口，平均每步误差仍为 3.002 mm / 1.228°，四步累计目标误差为 10.994 mm / 4.742°；0.05 / 0.1 rad 通过数为 151/165、164/165。未采样的 11 个窗口不能解释训练来源上的整体误差。

前四步旋转向量分量的平均绝对值，教师 train/dev 为 0.000975 / 0.001195 rad，学生为 0.010508 / 0.010534 rad，约为教师的 9–11 倍。这里比较的是 **rotvec 分量幅度**，不是角度误差的倍数。旋转通道没有触发最终 clamp，不能归因于旋转被截断。大量 clamp 出现在夹爪通道；原 Reach 执行固定开爪，本轮不将它认定为停止原因。

## 失败记录与边界

初次采样测试因旧 probe 的目录相关 import 失败，改为最小合成 fixture 后通过，失败日志保留。第一次诊断的前置几何核验发现原 float32 FK 旋转在反复组合 16 步后累积非正交误差：22/264 窗口在第 12–16 步触发原 SE(3) 校验，前四步全部正常。没有修改原几何函数或放宽校验；本轮将累计几何诊断限定为前四步，保留 16 步动作误差。失败的 `diagnostic-v1` 尚未开始模型推理，记录保留；成功推理仅运行 `diagnostic-v2`。该长前缀数值现象不解释历史 3–8 步停止。

SAPIEN 报告系统 Vulkan / ICD 缺失并尝试内置 fallback；本轮离线 FK/IK 完成，渲染与完整仿真环境尚未验证。

单噪声、教师状态离线诊断不能证明 PD 跟踪、Reach、闭环成功或 Memory 的因果收益。Train 与 development 接近支持优先调查拟合/输出尺度/去噪过程，但不能唯一归因于 256 次更新不足、初始化、归一化选择或 Euler 步数。恢复输入和原 MAE 一致也不能证明原方法本身没有问题。

建议下一步做固定少量训练窗口的有界过拟合与去噪诊断：检查训练目标下降是否对应物理旋转误差下降，再决定是否扩大训练；另行用策略实际访问的状态定位闭环分歧。本轮未启动这些后续实验。
